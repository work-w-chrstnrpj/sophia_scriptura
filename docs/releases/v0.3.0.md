# Sophia Scriptura v0.3.0

Release date: **2026-10-09**. App version **0.3.0**, build **20**.

## Canvas ink

Canvas handwriting now uses compound ink regions with internal stroke IDs, spatial hit testing and independent stroke editing. Strokes do not consume individual top-level canvas-object slots. Select, copy, move, recolor or delete a stroke/subset while preserving the surrounding ink, object transforms, layer order and undo history. Larger drawings spill into additional regions at explicit safety limits.

This replaces arbitrary 64-stroke batches as the editing unit. The reported 300-object ceiling was not established as a framework limit; the existing 1,000-object and payload/archive safety bounds remain. No unlimited capacity, measured device-speed improvement or complete Freeform parity is claimed. See [SP-025](../../tickets/SP-025-v030-compound-ink-and-stroke-editing.md).

## Notes and Collections locks

Set an app access lock on selected notes or collections, unlock with Touch ID or a shared backup password, and remove protection after authentication. Notes and Collections retain independent category sessions: one unlock grants access to the protected items in that category, and each category relocks after ten minutes idle and on app relaunch. Category controls can force-lock or authenticate to unlock protected items.

Locked cards show a gray appearance and lock icon. Locked menus omit editing; rename/color changes are guarded, while Archive/Delete remain available. Settings provides combined Lock All and Unlock All actions for items that already have protection set up. These actions do not add protection to other items. App startup does not present a Sophia Protected screen.

Protection is an **app access lock, not encryption**. Protected content and backups retain existing storage formats. Missing or foreign device credentials fail closed. Export/restore requires applicable access and retains current protection bindings for matching items. See [the protection contract](../security/item-protection.md) and [SP-026–028](../../tickets/SP-026-v030-lock-authentication-and-lifecycle.md).

Review fixes preserve shared-note opening through an unlocked collection even when another membership is locked; retaining an unchanged locked membership no longer blocks permitted filing changes. Rejected filing stays open with an explanation. Trash hides private tags and body-search matches for collection-hidden notes.

## Journal and Activity

Journal entries support optional Emotional State and Mental State fields, with descriptions for mental-state choices. Existing journals open with empty values; unknown stored values do not discard the entry. Accepted native editor buffers are flushed before protected content is concealed.

Activity has a separate **Scripture Contemplation** section with Start and filtered history. Its activity type is **Contemplating**, and the section omits a separate Today duration line. Independent Settings choices control automatic Reading and Contemplation workflows, both enabled by default. Disabling a workflow starts only its timer, without required passage selection or guided routing. Existing guided journeys and Reading range capture remain available when enabled; changing Settings does not restart a running activity.

Completed Quiz Me sessions contribute active time to **Studying**. Reviewing is removed from built-in choices. Legacy Reviewing records, drafts, reminders and goals migrate to Studying while retaining recorded time, IDs and quiz links; Studying/Reviewing goal allocations are combined without changing the total.

## Compatibility and verification

Notes and Collections keep atomic generation recovery and prior-data safeguards. Unprotected stores retain Notes schema 3 / Collections schema 1; protected stores use Notes schema 4 / Collections schema 2, which older apps reject rather than silently discarding locks. Existing v0.2 backups remain readable; current bindings for matching protected items survive restoration. Ink stroke IDs and Journal fields are additive. Activity keeps its v1 envelope, persisted `meditating` mode ID and legacy Companion quiz wire keys. Back up study data before downgrading; older builds do not enforce these access locks or preserve all new editing semantics.

The final version 0.3.0/build 20 snapshot passed **265 unit tests and four focused UI flows**, with zero failures, in `build/v030/release-acceptance.xcresult`: optional Activity workflows and labels, lock/category/combined controls and relaunch/password change, shared-note filing with a locked membership retained, and independent stroke select/copy/delete/paste/undo. The staged-file, credential-pattern and relative documentation-link audits passed. Only release documentation changed after this code verification.

Signed Debug feature builds were installed in place and launched on the owner's iPad A16 without uninstalling or resetting data before the release version bump. Release-snapshot verification is recorded in [the test specification](../testing/test-specification.md). The hosted Release workflow independently builds and runs the full unit suite before creating the tag and GitHub Release.

Physical Pencil/erasure/performance, Touch ID failure/cancel/lockout, long idle/cross-category behavior, audio, accessibility, Dynamic Type and complete device workflow acceptance remain pending. Installation and automated checks do not close those gates. See the ticket walkthroughs and [deployment guide](../deployment/deployment.md).

This is a personal source release. No personally provisioned IPA or study data is attached.
