# SP-055 — Plan creation, optional Catch up and Prayer actions

- Milestone: Collection Plans follow-up and owner-selected Prayer polish, 2026-10-30.
- Status: implemented; simulator verified; signed iPad install/launch verified; physical owner acceptance open.
- Dependencies: SP-053/054, existing Collections/Activity/Notes writers.

## Scope and acceptance

1. `Sam` → `Sample Plan` incremental autosaves must keep the same owned folder and update its complete name. Existing accessible mismatches are repaired by the existing startup/foreground adoption path. Preserve custom folder description, location, ID and contents.
2. Finishing a saved new Plan closes both the editor and Add Items; no extra Done tap. Canceling an empty unsaved creation may return to Add Items.
3. Remove all Custom due date switches/pickers. Retain optional stored keys for compatibility. When strict dates contain overdue unfinished assignments, Edit offers optional Catch up from today. Clicking it schedules all unfinished days in order from today; completed days keep dates and checked assignments remain checked. Opening Edit alone does not change a schedule. Due/completion captions appear in Edit for the Plan and each section.
4. Move Prayer Clear into More actions, retaining the existing confirmation and clear behavior.
5. Exiting/stopping halfway retains checked assignments and a paused resumable timer, with no History record. Only completed day/section playback records its Activity. Ordinary Activity Finish becomes Pause Plan for Plan drafts and cannot auto-check unfinished work. Legacy History is retained and cannot auto-complete unchecked assignments.

## Diagnosis and implementation ownership

CollectionsStore originally set root names only when creating the folder. Debounced autosave could create `Sam`; later saves of `Sample Plan` updated the Plan but not the root. Its checked save now synchronizes the name and only autogenerated descriptions. The previous root-description regression is retained to protect custom text. CollectionArtifactPicker owned the parent modal but the editor dismissed only itself; the parent now awaits nested dismissal after a saved finish, then dismisses Add Items.

PlanSchedule owns availability, calendar catch-up and shared date captions; PlanEditorDraft/View own explicit editing/autosave. Existing dueDate values store catch-up results. ActivityStore retains timer/history ownership; PlanPlaybackService verifies complete assignments before finishing. Ordinary Plan Activity Finish pauses and never creates a record. NotePrayerEditorView owns the moved Clear presentation; NotesSession commands remain unchanged.

Exclusions: provider changes, Plan Pencil/full reader lease, source release/commit/push, data deletion/conversion or historical History cleanup. Owner-authorized iPad installation/testing from this chat remains available after verification. No schema changes or reset.
